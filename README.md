# 折页阅读顺序校样（Fold Reader Proof）

一个用于校验**行列纸格折叠后阅读顺序**的 Web 应用。在行列纸格的每一格正反面标注页码，
然后依次添加“沿当前网格线向左 / 右 / 上 / 下折叠”的步骤，系统逐步模拟：

- 面片翻转后的**正反面**；
- 折叠后的**上下层级**（哪些纸压在下面）；
- 每个页码的**朝向**（正立 / 倒置 / 侧向）；
- 可**回放任一步**，查看任意折叠瞬间；
- 输出最终**从封面到封底**的完整页码序列（含翻页后的后半本）。

当折线**不在当前外轮廓内**（翻出的纸会悬空）或折线**两侧厚度不一致**（层数对不上、无法齐整折叠）时，
系统会拒绝执行，并在画布上用红色标出冲突纸格。

方案可保存为 JSON（服务器持久化），也可导出 / 导入 JSON 文件后重新载入。

## 技术栈

- 后端：Node.js + Express（静态页面 + 方案存取 REST API）
- 前端：原生 HTML / CSS / Canvas，无任何前端框架
- 折叠模拟核心：`public/fold.js`（浏览器与 Node 共用，附带断言测试）
- 部署：Docker + Docker Compose，**依赖安装与数据目录初始化全部纳入容器启动脚本**

## 一条命令启动

```bash
docker compose up --build
```

启动后浏览器打开：

**http://localhost:3000**

> 容器首次启动时会自动执行 `npm install`（依赖仅安装在容器内）并创建数据卷目录，
> 无需在宿主机准备任何依赖。停止后重新 `docker compose up` 即可，已保存方案持久化在
> Docker 卷 `fold-data` 中。

不使用 Docker 本地运行（需要 Node.js ≥ 20）：

```bash
npm install
npm start          # http://localhost:3000
```

运行引擎测试：

```bash
npm test
```

## 使用说明

### 1. 编辑纸格

- 设置**行数 / 列数**（1–12）后点击“应用”；
- 画布上每个格子上半部为**正面**（蓝色）、下半部为**反面**（橙色）；
- 点击某格，在左侧输入该格正面、反面页码；
- “自动正反编号”按行优先为每格依次填入 1|2、3|4 ……；
- 应用默认载入一个 **2×2 / 8 页经典折手**示例。

### 2. 折叠校样

- 切换到“② 折叠校样”，先点方向按钮（向**左 / 右 / 上 / 下**折）；
- 画布上沿当前外轮廓画出可选格线：
  - **绿色实线**：当前可执行的合法折线（悬停加粗并显示折叠方向箭头）；
  - **淡红虚线**：该折线不合法；
- 点击格线即执行折叠。非法操作会被拒绝，顶部给出原因，
  画布用**红色高亮冲突纸格**（悬空格或厚度不一致的落点格）。
- “折叠步骤”列表可点击跳转到任一步；回放条 ⏮ ◀ ▶ ⏭ 可逐步回放。

折叠方向的含义：

| 方向 | 动作 |
|----|----|
| 向左折 L | 竖线**右侧**的纸绕竖线翻到左边 |
| 向右折 R | 竖线**左侧**的纸绕竖线翻到右边 |
| 向上折 U | 横线**下侧**的纸绕横线翻到上边 |
| 向下折 D | 横线**上侧**的纸绕横线翻到下边 |

### 3. 阅读顺序

折叠为完整一叠后，左下“最终阅读顺序”给出封面 → 封底的页码块：

- 前半：自上而下各面片**朝上可见**的面；
- `翻页 ↩` 标记处之后：模拟翻页后，自下而上各面片**朝下隐藏**的面；
- 色块：蓝=正面、橙=反面；绿框=封面；页码倒置时鼠标悬停可看到旋转角度；
- 若尚未折成一叠（存在多个分离纸堆），会红字提示剩余纸堆数。

### 4. 保存 / 载入 / 导入 / 导出

- “保存到服务器”：方案以 JSON 持久化到容器数据卷，左下“已保存方案”可随时载入或删除；
- “导出 JSON”：下载方案文件；“导入 JSON”：从文件恢复方案；
- 方案 JSON 结构见下。

## 方案 JSON 结构

```json
{
  "version": 1,
  "name": "示例：8 页折手",
  "rows": 2,
  "cols": 2,
  "labels": [
    { "front": "5", "back": "4" },
    { "front": "3", "back": "6" },
    { "front": "1", "back": "8" },
    { "front": "7", "back": "2" }
  ],
  "steps": [
    { "dir": "L", "axis": 0.5 },
    { "dir": "D", "axis": 0.5 }
  ]
}
```

- `labels` 按**行优先**排列（`y * cols + x`），页码均为字符串，允许空串。
- `steps[].axis` 为折线坐标：竖线用 x 坐标、横线用 y 坐标，
  格线位于相邻两格中心之间，因此为半整数（如列 0 与列 1 之间为 `0.5`）。

## 折叠模型与校验规则

每个面片在内部用一个仿射坐标架表示：局部 x/y 轴在世界平面中的方向向量 `(ux,uy)`、
`(vx,vy)`，以及正面法向符号 `n`（+1 正面朝上，−1 反面朝上）。绕竖 / 横格线翻转 180°
时相应轴分量取反、法向翻转，由此得到精确的正反面与文字朝向。

折叠时以每个格位上**纸堆最底层的锚定面板**判定其位于折线哪一侧（上层为此前折叠落下的
纸，随锚点整堆移动）；翻片镜像到对侧后穿到基堆下方，翻片内部层级整体反转。

一次折叠被拒绝的情形：

| 错误码 | 含义 | 冲突标记 |
|----|----|----|
| `NO_FLAP` / `NO_BASE` | 折线某一侧根本没有纸（超出当前外轮廓） | — |
| `OUTLINE` | 翻片镜像落点超出纸张范围，折后会悬空 | 悬空的翻片格 |
| `THICKNESS` | 折叠落点两侧纸堆层数不一致 | 厚度不匹配的落点格 |
| `ON_LINE` | 折线穿过纸格中心而非沿格线 | 被穿过的格 |

## REST API

| 方法 | 路径 | 说明 |
|----|----|----|
| GET | `/api/schemes` | 已保存方案列表 |
| GET | `/api/schemes/:id` | 读取单个方案 JSON |
| POST | `/api/schemes` | 保存（自动生成 id） |
| DELETE | `/api/schemes/:id` | 删除方案 |
